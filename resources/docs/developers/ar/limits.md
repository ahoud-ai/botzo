# الحدود والسرعة

## حدود الطلبات

| الحد | القيمة | ينطبق على |
| --- | --- | --- |
| طلبات الـ API | 120 طلباً في الدقيقة | كل المؤسسة، لكل المفاتيح السرية معاً |
| مفتاح موتشي العام | 60 طلباً في الدقيقة | لكل جهاز (عنوان IP) |
| محادثات موتشي جديدة بالمفتاح العام | 10 في الساعة | لكل جهاز (عنوان IP) |
| رسائل في محادثة موتشي | 30 في الساعة، وبينها 3 ثوانٍ على الأقل | لكل محادثة |
| ردود موتشي في اليوم | حسب إعدادات المؤسسة (الافتراضي 300) | كل محادثات الويب وAPI موتشي |
| الـ Webhooks | حتى 3 روابط | لكل مؤسسة |

تجاوز حد الدقيقة يرجع:

```json
{
  "statusCode": 429,
  "code": "rate_limited",
  "message": "Too many API requests. Please retry shortly.",
  "request_id": "…"
}
```

ومعه الهيدرز `Retry-After` (بالثواني) و `X-RateLimit-Limit` و `X-RateLimit-Remaining`. انتظر المدة في `Retry-After` قبل الإعادة.

## حدود الباقة

باقة المؤسسة تحدد عدد الرسائل في دورة الاشتراك، وعدد جهات الاتصال، والحملات، والردود التلقائية. عند الوصول لأي حد يرجع `403` بكود يوضح أيه (`message_limit_reached`، `contacts_limit_reached`…). الترقية من لوحة التحكم ← الفوترة والاشتراك.

## حدود واتساب (Meta)

Meta تضع حدوداً على رقمك نفسه، بعيداً عن بوتزو:

- **عدد العملاء الجدد** الذين تبدأ معهم محادثة بقالب في 24 ساعة (يبدأ بـ 250 أو 1000، ويزيد مع جودة رقمك وحجم استخدامه).
- **سرعة الإرسال** في الثانية (`meta_rate_limited`).
- **رسائل متتالية لنفس العميل** في وقت قصير (`recipient_rate_limited`).

تقييم رقمك وحدوده الحالية في **WhatsApp Manager** في حساب Meta.

## السرعة المتوقعة

| العملية | الزمن المعتاد | ملاحظات |
| --- | --- | --- |
| أي طلب داخل بوتزو (بدون واتساب أو ذكاء اصطناعي) | أقل من 50 ملّي ثانية | |
| إرسال رسالة واتساب | 0.5 إلى 1.5 ثانية | أغلبه وقت خوادم Meta |
| رد موتشي (`wait=true`) | 2 إلى 5 ثوانٍ | وقت الذكاء الاصطناعي |
| إرسال لموتشي بدون انتظار (`wait=false`) | أقل من 100 ملّي ثانية | الرد يأتي بعدها بثوانٍ |
| وصول Webhook بعد رسالة العميل | أقل من ثانيتين | بعد أن تخبرنا Meta |
| بدء الحملات المجدولة | خلال دقائق من موعدها | الحملات تخرج على دفعات |

### اعرف أين ذهب الوقت: Server-Timing

كل رد من الـ API فيه الهيدر `Server-Timing`:

```http
Server-Timing: app;dur=1052.4, db;dur=12.7, token;dur=1.2, meta;dur=1010
```

| القيمة | المعنى |
| --- | --- |
| `app` | زمن الطلب كله داخل بوتزو |
| `db` | قاعدة البيانات |
| `meta` | انتظار خوادم واتساب |
| `token` | تجهيز ربط واتساب |

في المثال: من 1052 ملّي ثانية، 1010 كانت عند Meta. لو طلب بطيء، `Server-Timing` و `request_id` هما أول ما نحتاجه منك.

## نصائح للأداء

- **أعد استخدام الاتصال (Keep-Alive)** بدل فتح اتصال جديد لكل طلب.
- **المهلة:** 30 ثانية لإرسال واتساب، و45 ثانية لموتشي مع `wait=true`.
- **الإعادة:** فقط على `429` و `5xx` و `502`، بانتظار متزايد (1، 2، 4، 8 ثوانٍ)، ومع `Idempotency-Key` للإرسال.
- **الإرسال الجماعي:** استخدم الحملات بدل حلقة على `/api/send`، فهي تنظم السرعة وحدود واتساب عنك.
- **استمع بدل أن تسأل:** الـ Webhooks تغنيك عن السؤال المتكرر عن حالة الرسائل وردود الموظفين.
