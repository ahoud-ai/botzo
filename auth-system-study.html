⚡ ٢ — ميزة Botzo كمزود WhatsApp

الفكرة الجوهرية: بدل ما تدفع لـ Twilio أو 360dialog لإرسال WhatsApp OTP، Botzo يستخدم بنيته التحتية الخاصة. كل عميل عنده WhatsApp Business Account موصول بـ Botzo — نفس الـ WhatsAppService يُستخدم لإرسال OTP لمستخدمي Botzo.

الهيكل الحالي للـ WhatsApp في Botzo

// app/Services/WhatsappService.php // Per-organization: each Botzo customer has their own WhatsApp credentials class WhatsappService implements MessagingGatewayContract { // Credentials stored in organizations.metadata['whatsapp'] protected $phoneNumberId; // Meta Phone Number ID protected $wabaId; // WhatsApp Business Account ID protected $accessToken; // Encrypted via WhatsappTokenVault sendTemplateMessage($contact, $template, ...) // ← نستخدم هذا لـ OTP sendMessage($contact, $content, ...) }

المقترح: Botzo System Account

ننشئ Organization مخصصة لـ "Botzo System" نحفظ فيها WhatsApp credentials الخاصة بـ Botzo (رقم الهاتف الرسمي للمنصة). هذا يفصل بين رسائل العملاء ورسائل النظام.

ما نحتاجه لإعداده

  • رقم هاتف مخصص لـ Botzo (غير مسجل على WhatsApp مسبقاً)
  • WhatsApp Business Account (WABA) خاص بـ Botzo كمنصة
  • Facebook Business Verification — ربما موجود بالفعل
  • Authentication Template معتمد من Meta
  • تخزين credentials في Settings table: key='botzo_whatsapp_config'

🗄️ ٣ — تصميم قاعدة البيانات

أ) تعديلات على جدول users

-- Migration: add_phone_verification_to_users_table Schema::table('users', function (Blueprint $table) { // 1. Track phone verification status $table->timestamp('phone_verified_at')->nullable()->after('email_verified_at'); // 2. Unique phone per active user (soft-delete aware) // MySQL treats (phone, NULL) as unique per row → allows soft-deleted duplicates $table->unique(['phone', 'deleted_at'], 'users_phone_active_unique'); // 3. Index for fast phone lookups during login $table->index('phone', 'users_phone_index'); });
ملاحظة Soft Deletes: MySQL يعامل NULL كقيمة فريدة بذاتها في UNIQUE indexes. لذلك (phone, deleted_at=NULL) يمكن أن يظهر مرة واحدة فقط للمستخدمين النشطين. المستخدمون المحذوفون لهم deleted_at بتاريخ مختلف فيُسمح بتكرار الهاتف. هذا نفس النهج المستخدم حالياً لحقل email.

ب) جدول verification_codes الموحّد (جديد)

نوحّد email + phone OTP في جدول واحد بدل جدولين منفصلين.

-- Migration: create_verification_codes_table (replaces email_verification_codes) Schema::create('verification_codes', function (Blueprint $table) { $table->id(); $table->foreignId('user_id')->nullable()->constrained()->nullOnDelete(); // The email address or E.164 phone number (+966501234567) $table->string('identifier', 255); // Channel: how to deliver the code $table->enum('channel', ['email', 'whatsapp', 'sms'])->default('email'); // Purpose: why is this code being sent $table->enum('purpose', [ 'register', // New account registration 'login', // Passwordless or 2FA login 'password_reset', // Forgot password 'verify_phone', // Phone verification for existing user 'verify_email', // Email verification for existing user ]); $table->string('code_hash'); // bcrypt of 6-digit code $table->timestamp('expires_at'); $table->timestamp('used_at')->nullable(); $table->tinyInteger('attempts')->unsigned()->default(0); $table->string('ip_address', 45)->nullable(); $table->timestamps(); // Fast lookup: find active code for identifier+purpose $table->index(['identifier', 'purpose', 'used_at', 'expires_at'], 'idx_lookup'); });

ب) Login Flow

// app/Http/Controllers/AuthController.php → login() public function login(LoginRequest $request) { $identifier = $request->input('identifier'); // email OR phone // Auto-detect: is it email or phone? if (filter_var($identifier, FILTER_VALIDATE_EMAIL)) { $user = User::where('email', $identifier)->whereNull('deleted_at')->first(); } else { $normalized = phone($identifier)->formatE164(); // existing helper $user = User::where('phone', $normalized)->whereNull('deleted_at')->first(); } // Generic error — don't reveal which field doesn't exist (security) if (! $user || ! Hash::check($request->password, $user->password)) { return back()->withErrors(['identifier' => 'بيانات الدخول غير صحيحة']); } // Check verification status if (! $user->hasVerifiedIdentifier()) { $this->otpService->resend($user); // resend OTP return redirect()->route('verification.notice'); } Auth::login($user, $request->boolean('remember')); return redirect()->intended(route('dashboard')); }

Rate Limiting Strategy

// AppServiceProvider::boot() RateLimiter::for('otp-send', fn($req) => [ // Per identifier: 3 OTPs per 15 min Limit::perMinutes(15, 3) ->by('otp:'.$req->input('identifier')), // Per IP: 10 OTPs per hour Limit::perHour(10) ->by('otp:ip:'.$req->ip()), ]); RateLimiter::for('otp-verify', fn($req) => // Max 5 verify attempts per 15 min per identifier Limit::perMinutes(15, 5) ->by('verify:'.$req->input('identifier')) );
Shared Hosting: لا يوجد Redis على Namecheap. استخدم CACHE_DRIVER=database. شغّل php artisan cache:table && php artisan migrate.

OTP Security Rules

  • 🔐
    Hash الكود بـ bcrypt — لا تخزن الكود نصاً صريحاً في DB
  • ⏱️
    Expiry: 15 دقيقة — كافي للمستخدم وقصير بما يكفي للأمان
  • 🚫
    Invalidate الأكواد القديمة عند كل طلب OTP جديد
  • 🔢
    Max attempts: 5 — بعدها يُلغى الكود، يجب طلب جديد
  • 🕵️
    Timing-safe comparison — استخدم hash_equals() وليس ==
  • 📝
    Log IP + User Agent لكل طلب OTP للمراقبة
  • 🤫
    Generic error messages — لا تكشف هل الهاتف/إيميل موجود أم لا
  • 🧹
    Cleanup — Cron job يحذف الأكواد المنتهية يومياً

📈 ٩ — التوسعية

الآن (Shared Hosting)

  • QUEUE_CONNECTION=sync
  • CACHE_DRIVER=database
  • OTP يُرسل synchronously
  • Rate limiting عبر DB cache
  • يدعم ~100-500 مستخدم نشط يومياً

المستقبل (VPS / Cloud)

  • QUEUE_CONNECTION=redis
  • CACHE_DRIVER=redis
  • OTP يُرسل via Queue (أسرع استجابة)
  • Horizontal scaling: متعدد workers
  • يدعم 10,000+ مستخدم نشط يومياً

مبادئ التصميم للتوسع

  • 1
    Channel Abstraction: UnifiedOtpService يخفي القناة — إضافة SMS أو Voice OTP لاحقاً دون تغيير الكود الأساسي
  • 2
    Purpose-based: نفس الجدول يخدم كل الأغراض — register, login, password_reset, phone_verify — بدون جداول متعددة
  • 3
    Template-ready: WhatsApp credentials في Settings table — يسهل تغيير رقم الـ OTP أو الـ template دون deploy
  • 4
    Fallback Channel: إذا WhatsApp فشل (رقم خاطئ/محظور) → SMS Fallback عبر نفس Service interface
